BLOQUE D — CREDENCIALES QUE NO SE PUEDEN EXTRAER Y HAY QUE GENERAR A MANO
===============================================================================
Punto 8 de tus reglas: se declara explicitamente.

1. META_PAGE_ACCESS_TOKEN
   NO se puede leer de ninguna pantalla. Se GENERA por flujo OAuth en el Graph
   API Explorer y despues se CANJEA por uno de larga duracion. Requiere que los
   permisos leads_retrieval / pages_show_list / pages_manage_metadata esten
   concedidos.

2. WHATSAPP_ACCESS_TOKEN
   Se GENERA en Business Manager creando un Usuario del Sistema y pulsando
   "Generar token". No existe en ninguna pantalla antes de generarlo. Solo se
   muestra UNA VEZ: si no lo copias en ese momento, hay que generar otro.

3. META_MARKETING_ACCESS_TOKEN
   Igual que el anterior, con alcance `ads_read`. Puede ser el MISMO Usuario del
   Sistema, pero es token aparte si quieres separar alcances.

4. META_WEBHOOK_VERIFY_TOKEN
   No viene de Meta: la generas tu con `crypto.randomBytes` y la escribes en los
   dos lados.

Solo META_APP_SECRET se puede LEER directamente de una pantalla (Configuracion ->
Basica -> Mostrar). Todo lo demas de esta lista se genera.

NO REGENERES nada que ya funcione. Regenerar el App Secret invalida la firma de
todas las entregas en vuelo; regenerar un token de Usuario del Sistema deja
WhatsApp mudo hasta que despliegues el nuevo valor.
